git-remote-tau(1)
=================

NAME
----
git-remote-tau - Tau-native transport helper for tau:// repositories

SYNOPSIS
--------
[verse]
'git clone' tau://<repository>
'git fetch' <tau-remote>
'git push' <tau-remote> <refspec>

DESCRIPTION
-----------

The Hermes Ark Git fork ships `git-remote-tau`, a remote-helper that makes
`tau://` repositories available to this Git client.

A `tau://` repository is Tau-native.  The helper publishes repository manifests
whose refs point to `tau:<hash>` object identities.  Git object names are kept as
compatibility metadata so the forked client can continue to materialize working
trees through Git's existing fast-import and fast-export machinery.

The initial payload codec is `git-raw-v1`: the stored payload for each object is
the normal serialized Git object byte stream:

	<object-type> <size>\0<body>

The Tau identity of that payload is a content address.  In local-only mode the
payload is stored under `GIT_TAU_STORE`.  When TauStorage client mode is enabled,
the helper uploads/downloads payloads and manifests through the networked
TauStorage/Autonomi-compatible client API.

STORAGE MODES
-------------

Local prototype store
~~~~~~~~~~~~~~~~~~~~~

By default, the prototype store lives at:

	$HOME/.git-tau/store

For tests or isolated repositories, set `GIT_TAU_STORE`:

	GIT_TAU_STORE=/tmp/tau-store git clone tau://demo

The store contains:

`objects/`::
	Content-addressed object payloads.

`repos/<name>/cache.git`::
	A local bare Git cache used to bridge Git fast-import/export while the payload
	codec is `git-raw-v1`.

`repos/<name>/latest.json`::
	The latest Tau-native manifest.  Refs in this manifest point to Tau object IDs,
	not Git object IDs.

TauStorage client API mode
~~~~~~~~~~~~~~~~~~~~~~~~~~

Set `GIT_TAU_DEVNET_MANIFEST` to enable networked TauStorage client mode.  The
helper then calls an Autonomi-compatible client command for every object payload
and manifest:

[listing]
----
ant file upload <payload> \
	--public \
	--devnet-manifest <manifest> \
	--allow-loopback \
	--evm-network <network>

ant file download <address> -o <output> \
	--devnet-manifest <manifest> \
	--allow-loopback \
	--evm-network <network>
----

Environment variables:

`GIT_TAU_CLIENT`::
	Client executable. Defaults to `ant`.

`GIT_TAU_DEVNET_MANIFEST`::
	Path to the TauStorage/Autonomi devnet manifest. Setting this enables
	TauStorage client API mode.

`GIT_TAU_EVM_NETWORK`::
	EVM network argument for the client. Defaults to `local`.

`GIT_TAU_STORE`::
	Local helper state, manifest pointer files, and bridge cache. Even in
	TauStorage client mode this remains the local working cache, not the canonical
	object store.

In TauStorage client mode, each object entry records the returned network
address:

[listing]
----
"<tau-hash>": {
  "kind": "blob",
  "payload_codec": "git-raw-v1",
  "git": { "hash_algorithm": "sha1", "oid": "<git-object-id>" },
  "taustorage": { "address": "tau://..." }
}
----

The latest manifest is also uploaded; its returned address is stored locally in:

	$GIT_TAU_STORE/repos/<name>/latest.addr

MANIFEST SHAPE
--------------

A published manifest contains fields like:

[listing]
----
{
  "schema_version": 1,
  "repository": "demo",
  "identity_mode": "tau-native",
  "payload_codec": "git-raw-v1",
  "refs": {
    "refs/heads/main": "tau:<hash>"
  },
  "objects": {
    "<tau-hash>": {
      "kind": "commit",
      "payload_codec": "git-raw-v1",
      "git": {
        "hash_algorithm": "sha1",
        "oid": "<git-object-id>"
      },
      "taustorage": {
        "address": "tau://<network-address>"
      }
    }
  },
  "git_to_tau": {
    "git:sha1:<git-object-id>": "<tau-hash>"
  }
}
----

LIMITATIONS
-----------

This is an MVP transport for the forked Git client.  Tau-native manifests,
network client upload/download plumbing, and `tau://` Git UX are in place.  The
current payload codec still uses `git-raw-v1` and a local bare Git bridge cache;
a future version can switch the payload codec to Tau-native commit/tree/blob
objects.
